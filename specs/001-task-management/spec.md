## Clarifications

### Session 2026-09-16

- Q: 새 할 일은 목록에서 어떤 순서로 표시해야 하나요? → A: 최신 생성 순서부터 표시

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Add a task (Priority: P1)

사용자는 해야 할 일을 제목으로 추가해 목록에 보관할 수 있다.

**Why this priority**: 할 일을 기록할 수 있어야 다른 관리 기능도 의미가 있다.

**Independent Test**: 새 제목을 입력해 저장한 뒤 해당 제목의 미완료 할 일이 목록에 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 유효한 제목을 입력한 상태, **When** 할 일을 저장하면, **Then** 새 할 일이 미완료 상태로 목록에 표시된다.
2. **Given** 제목이 비어 있거나 공백만 있는 상태, **When** 사용자가 저장을 시도하면, **Then** 할 일은 추가되지 않고 입력 오류를 알린다.

---

### User Story 2 - View the task list (Priority: P1)

사용자는 저장된 할 일의 제목과 완료 여부를 한 목록에서 확인할 수 있다.

**Why this priority**: 현재 해야 할 일과 완료된 일을 파악하는 핵심 사용 흐름이다.

**Independent Test**: 서로 다른 시각에 여러 상태의 할 일을 준비한 뒤 목록을 열어 모든 항목과 각 상태가 표시되고 최신 항목이 먼저 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 저장된 할 일이 있는 상태, **When** 사용자가 목록을 확인하면, **Then** 각 할 일의 제목과 완료 여부가 표시된다.
2. **Given** 저장된 할 일이 없는 상태, **When** 사용자가 목록을 확인하면, **Then** 목록이 비어 있음을 이해할 수 있는 안내가 표시된다.
3. **Given** 서로 다른 시각에 추가된 할 일이 있는 상태, **When** 사용자가 목록을 확인하면, **Then** 가장 최근에 추가된 할 일이 가장 위에 표시된다.

---

### User Story 3 - Toggle completion (Priority: P2)

사용자는 할 일의 완료 여부를 전환해 진행 상태를 관리할 수 있다.

**Why this priority**: 사용자가 완료한 일과 남은 일을 구분하게 해준다.

**Independent Test**: 미완료 항목을 완료로 전환하고 다시 미완료로 전환해 두 상태가 각각 저장되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 미완료 할 일이 목록에 있는 상태, **When** 사용자가 완료 처리를 하면, **Then** 해당 할 일이 완료 상태로 표시된다.
2. **Given** 완료된 할 일이 목록에 있는 상태, **When** 사용자가 완료 해제를 하면, **Then** 해당 할 일이 미완료 상태로 표시된다.

---

### User Story 4 - Delete a task (Priority: P2)

사용자는 더 이상 관리하지 않을 할 일을 목록에서 삭제할 수 있다.

**Why this priority**: 오래되거나 잘못 추가한 항목을 정리할 수 있게 해준다.

**Independent Test**: 목록의 할 일을 삭제한 뒤 해당 항목이 더 이상 표시되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 삭제할 할 일이 목록에 있는 상태, **When** 사용자가 삭제하면, **Then** 해당 할 일이 목록에서 사라진다.
2. **Given** 이미 삭제되었거나 존재하지 않는 할 일을 삭제하려는 상태, **When** 삭제를 요청하면, **Then** 시스템은 상태를 잘못 변경하지 않고 실패를 알린다.

---

### Edge Cases

- 제목 앞뒤의 공백은 유효성 검사 전에 제거하며, 공백 제거 후 비어 있으면 저장하지 않는다.
- 목록에 할 일이 없을 때 빈 목록 안내를 표시한다.
- 완료 여부를 이미 원하는 값으로 설정한 항목에 같은 동작을 요청해도 최종 상태는 요청한 상태와 일치해야 한다.
- 존재하지 않는 할 일을 완료 처리하거나 삭제하려는 요청은 데이터 변경 없이 실패해야 한다.
- 저장 또는 상태 변경에 실패하면 사용자는 작업이 완료되지 않았음을 알 수 있어야 하며, 기존 목록은 임의로 사라지지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 제목을 입력해 새 할 일을 추가할 수 있어야 한다.
- **FR-002**: 할 일의 제목은 필수이며, 공백만으로 구성된 제목은 허용하지 않아야 한다.
- **FR-003**: 새로 추가된 할 일은 기본적으로 미완료 상태여야 한다.
- **FR-004**: 사용자는 저장된 할 일의 제목과 완료 여부를 목록에서 확인할 수 있어야 한다.
- **FR-005**: 저장된 할 일이 없을 때 시스템은 빈 목록 상태를 명확히 표시해야 한다.
- **FR-005a**: 목록은 할 일을 최신 생성 순서부터 표시해야 한다.
- **FR-006**: 사용자는 할 일의 완료 여부를 완료와 미완료 사이에서 전환할 수 있어야 한다.
- **FR-007**: 사용자는 저장된 할 일을 삭제할 수 있어야 한다.
- **FR-008**: 존재하지 않는 할 일에 대한 완료 상태 변경 또는 삭제 요청은 데이터 변경 없이 실패해야 한다.
- **FR-009**: 작업 실패 시 시스템은 사용자가 실패 사실과 재시도 가능 여부를 알 수 있는 오류 안내를 제공해야 한다.
- **FR-010**: 할 일 데이터는 사용자가 목록을 다시 확인해도 유지되어야 한다.

### Key Entities

- **Task**: 사용자가 관리하는 하나의 할 일을 나타내며, 필수 제목과 완료 여부를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 30초 이내에 제목이 있는 할 일을 추가하고 목록에서 확인할 수 있다.
- **SC-002**: 사용자는 목록의 각 할 일에서 현재 완료 여부를 한 번의 확인으로 식별할 수 있다.
- **SC-003**: 사용자는 완료 여부 전환 후 3초 이내에 변경된 상태를 확인할 수 있다.
- **SC-004**: 사용자는 삭제 후 삭제한 항목이 목록에 남아 있지 않음을 확인할 수 있다.
- **SC-005**: 유효하지 않은 제목이나 존재하지 않는 항목을 대상으로 한 작업은 데이터 변경 없이 거부된다.
- **SC-006**: 사용자가 새로고침 또는 목록 재진입 후에도 이전에 저장한 할 일을 확인할 수 있다.

## Assumptions

- v1의 사용자는 별도 역할이나 권한 구분이 없는 단일 사용자다.
- v1에서는 제목 수정, 검색, 필터링, 정렬, 마감일, 우선순위, 반복 일정 기능을 범위에서 제외한다.
- 할 일 목록은 일반적인 개인 작업량을 전제로 하며 대규모 협업이나 동시 편집은 지원하지 않는다.
- 사용자는 작업을 수행하는 동안 애플리케이션에 접근할 수 있다.
- 저장된 데이터는 사용자가 명시적으로 삭제하기 전까지 유지된다.
